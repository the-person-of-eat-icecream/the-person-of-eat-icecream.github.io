这是一篇实践笔记的示例，展示代码、步骤与旁注的排版方式。

## 先找到一个具体的问题

“我想学习编程”是一个很大的愿望。“我想做一个可以记录读书进度的小页面”，则已经足够具体，可以开始动手。

把目标缩小，通常不是降低期待，而是让第一步真正发生。

<aside>一个好起点：用一句话说清楚，这个小东西帮谁解决了什么问题。</aside>

## 写下最小的版本

不必马上加上所有功能。一个输入框、一段文字、一个保存按钮，就可以是完整的开始。

```python
def make_progress(pages_read, total_pages):
    if total_pages <= 0:
        return 0
    return min(100, round(pages_read / total_pages * 100))

print(make_progress(42, 240))
```

代码可以很短，但它把一个模糊的想法变成了可以验证的行为。

## 让反馈决定下一步

做出第一版后，试着使用它，然后记下三个问题：

1. 哪个地方比想象中好用？
2. 哪个操作让人停顿了？
3. 如果只能改一处，最值得改什么？

这些答案，比一张冗长的功能清单更能帮助我们找到方向。

## 把过程也保存下来

最终的作品值得展示，过程中走过的弯路也值得记录。把问题、尝试和选择写下来，下次遇到相似的场景，就有了自己的参考。
